# AI 導覽小幫手 + 智慧門鎖自助入住

> 關聯評估項目：民宿業 / C.住客體驗 / 客戶體驗 / CX-01  
> 方案代碼：`BNB_C_CX_01`

## 1. 方案摘要
- **解決痛點**：入住等候/櫃台無人、夜間/多語言客服缺口、景點餐飲推薦不標準、住客偏好無記錄
- **核心價值**：前台人力 -30%、住客滿意度 ↑、24/7 多語言即時回應、自助入住零等待
- **適用對象**：10 間以上、有夜間入住需求、外籍客比例 >20%、想降低前台人力成本

## 2. 詳細實施步驟
| 階段 | 任務 | 產出物 | 負責角色 | 工時估算 |
|------|------|--------|----------|----------|
| 1. 需求釐清 | 整理常見問答（FAQ）、景點/餐飲/交通資料、多語言術語表 | FAQ 文件、景點資料庫、術語表 | 顧問/業主 | 8h |
| 2. 知識庫建置 | 將 FAQ/景點/餐飲/交通/SOP 匯入 RAG 知識庫、設定檢索參數 | Dify/Coze 知識庫、測試問答紀錄 | 顧問/工程師 | 16h |
| 3. Bot 開發串接 | 建置 Line Bot/網頁聊天介面、串接知識庫、設計對話流程、多語言切換 | 可測試 Bot、API 文件 | 工程師 | 24h |
| 4. 智慧門鎖整合 | 採購/安裝門鎖、設定臨時密碼/臉辨/Line 通知流程、與 PMS 同步訂單 | 門鎖系統、自動發碼流程 | 工程師/廠商 | 16h |
| 5. 測試驗收 | 實地模擬入住/問答/異常處理、多語言測試、負載測試 | 測試報告、問題清單 | 顧問/業主/工程師 | 8h |
| 6. 上線/移交 | 員工操作訓練、住客引導貼紙/QR Code 佈放、操作手冊交付 | 訓練紀錄、手冊、上線確認單 | 全員 | 8h |

**總工時估算：約 80h（2 週）**

## 3. 工具/技術選型建議
| 類別 | 推薦方案 | 優點 | 缺點 | 估算成本 |
|------|----------|------|------|----------|
| **RAG/平台** | **Dify (雲端/自架)** | 視覺化流程、內建 RAG、多模型、API 完整、免費額度大 | 進階功能需自架 | $0-5,000/月 |
| | **Coze (字節跳動)** | 中文優化、插件豐富、免費額度高、部署簡單 | 資料主權在海外、自訂度較低 | $0-3,000/月 |
| | **自建** | 完全掌控、資料不出去、可深度客製 | 開發維運成本高 | 開發 $10-30萬 + 維運 |
| **智慧門鎖** | **Igloohome** | 免網路發碼、離線密碼、API 開放、耐用 | 價格較高 | $4,000-8,000/把 |
| | **RemoteLock** | 雲端管理、多平台同步、API 完整 | 需穩定網路 | $3,500-7,000/把 + 訂閱 |
| | **國產品牌** | 價格親民、本地支援、符合法規 | API 可能較簡單 | $2,000-5,000/把 |
| **前端介面** | **Line Bot (官方帳號)** | 國人習慣、免安裝、推播免費、Rich Menu 導覽 | 需審核、功能受限 | 免費(含推播額度) |
| | **網頁聊天** | 不綁平台、可嵌入官網、自訂 UI | 住客需主動開啟 | 開發成本含在 Bot 內 |

## 4. 資料需求與前置條件
- **必備資料**：
  - 常見問答（入住/退房/設施/周邊/交通/政策）至少 50 組 Q&A
  - 景點/餐飲/體驗/交通資料（名稱、地址、電話、營業時間、特色、推薦理由、距離、照片）
  - 房型/設施/備品/政策說明（中/英/日/韓 至少雙語）
  - 歷史客服紀錄（可作為補充訓練資料）
- **系統前置**：
  - PMS 已上線且有 API/Webhook（用於訂單觸發發碼）
  - Line 官方帳號已認證
  - 穩定網路環境（門鎖若用雲端型）
- **人員前置**：
  - 一位懂業務、會整理資料的專案窗口（0.5 FTE，2 週）
  - IT 支援或外包工程師（負責 Bot 部署、門鎖 API 串接）

## 5. 風險與對策
| 風險 | 機率 | 影響 | 緩解對策 |
|------|------|------|----------|
| FAQ/景點資料不全、錯誤 | 高 | Bot 回答不準、住客抱怨 | 分批上線：先上線核心 FAQ，景點資料持續補充；設定「無法回答時轉人工」 |
| 門鎖發碼失敗/不同步 | 中 | 住客進不去房、投訴 | 保留實體鑰匙備援、前台/管委會備份開鎖碼、測試階段雙軌制 |
| 多語言翻譯不自然 | 中 | 外籍客體驗差 | 用 DeepL/Google 翻譯初稿 → 母語者校對 → 設定術語表鎖定關鍵詞 |
| 員工抗拒/不會用 | 中 | 系統閒置、仍靠人工 | 高層背書、共創設計流程、遊戲化（首月使用率排名獎勵）、快速參考卡貼櫃台 |
| Line 官方帳號審核不通 | 低 | 無法推播/用 Bot | 提前準備隱私權/服務條款網頁、用網頁聊天版作備援 |
